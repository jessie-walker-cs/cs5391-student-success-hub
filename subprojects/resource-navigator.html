Student Resource Navigator

Make official university information easier to discover, understand, and verify.

Select this subprojectCollaboration standards

Problem and purpose

Online students can struggle to locate the right office or official resource for registration, learning platforms, advising, and student services. A curated public-resource directory can help users find information quickly without representing itself as official advice.

Scope and minimum viable product

Build a responsive, searchable directory with approximately 10 to 15 verified public university resources. Do not scrape private systems or collect student information.

Required capabilities

  • Search resource titles, descriptions and plain-language tags.
  • Filter resources by categories including registration, technology, graduate support and billing.
  • Display summaries, official HTTPS links and the dates links were checked.
  • Provide accessible no-results states, keyboard navigation and mobile layouts.
  • Publish consistent resource IDs and JSON records for the other two teams.

Example user journey

A student searches for “Canvas access,” finds technology assistance, and opens the official support link.

Development tasks across three Agile sprints

  1. Sprint 1: Populate sample resource records and create basic directory pages.
  2. Sprint 2: Add search, filters, mobile presentation and verification metadata.
  3. Sprint 3: Stabilize resource IDs, integrate with other teams and resolve usability defects.

Write detailed user stories, acceptance criteria and technical decisions in your team SRS and design document. This guidance supplements, but does not replace, Canvas rubrics.

Team roles and possible contributions

  • Requirements lead: define search scenarios, user stories and acceptance criteria.
  • Content/data lead: check public resource URLs and write concise descriptions.
  • Developer: implement searchable cards, filters and responsive detail views.
  • Test lead: evaluate empty states, broken URLs, keyboard access and usability.

Roles are responsibilities within the selected subproject. Students may rotate them while remaining on the same subproject team.

Acceptance criteria and testing

  • Search returns a relevant result based on a title or tag.
  • Category filtering consistently limits results.
  • Missing results produce a helpful message.
  • Every link leads to a real public university resource.
  • Sample data contains no confidential student information.

How this team works with the other two teams

  • Provide Team 3 with stable resource IDs and official support URLs.
  • Provide Team 2 with official AOP and campus calendar resource links.
  • Coordinate site navigation, terminology, shared JSON interfaces and integration tests.

Optional enhancements

  • A resource freshness indicator.
  • Enhanced search shortcuts and usability testing.

Optional work requires instructor approval and must not prevent a complete, tested minimum product.
