Academic Planner

Help students plan an accelerated term without depending on a Canvas integration.

Select this subprojectCollaboration standards

Problem and purpose

Accelerated students juggle assignments and deadlines within a compressed eight-week period. An accessible planner can help them manage their own work and identify university breaks without claiming to copy Canvas deadlines.

Scope and minimum viable product

Create a browser-based planner with fictional example coursework, manual task entry and localStorage persistence. No accounts, Canvas API tokens, remote database or notification infrastructure are required.

Required capabilities

  • Display the Thursday through Wednesday planning weeks alongside the distinct project-module windows in the syllabus.
  • Identify October Fall Break and November Thanksgiving dates as university calendar events.
  • Create, edit, mark complete and delete manually entered tasks.
  • Filter tasks by upcoming, completed and overdue, with accessible date validation.
  • Persist demonstration tasks in localStorage and provide a clear reset function.

Example user journey

A student adds a fictional SRS deadline, marks the task complete, and refreshes the page to confirm it remains completed.

Development tasks across three Agile sprints

  1. Sprint 1: Display the term and seeded fictional tasks.
  2. Sprint 2: Implement add, edit, complete, delete and form validation.
  3. Sprint 3: Integrate resource links, improve task views and test storage and accessibility.

Write detailed user stories, acceptance criteria and technical decisions in your team SRS and design document. This guidance supplements, but does not replace, Canvas rubrics.

Team roles and possible contributions

  • Product lead: define student scheduling scenarios and acceptance criteria.
  • Interface developer: build accessible task forms and schedule views.
  • Data developer: implement local persistence and reliable state management.
  • Tester: verify unusual dates, time calculations, keyboard use and reset behavior.

Roles are responsibilities within the selected subproject. Students may rotate them while remaining on the same subproject team.

Acceptance criteria and testing

  • Users can add, edit, complete and delete a sample task.
  • Invalid dates are rejected with useful messages.
  • Local changes survive a browser refresh.
  • Holiday dates are distinguished from official Canvas due dates.
  • Sample records can be cleared without transmitting user records.

How this team works with the other two teams

  • Use Team 1 public calendar and resource records rather than copying them.
  • Link to Team 3 when users need support with registration or course access.
  • Follow the shared site navigation and integration agreements.

Optional enhancements

  • Export sanitized sample tasks as JSON.
  • Summarize completion progress across weeks.

Optional work requires instructor approval and must not prevent a complete, tested minimum product.
